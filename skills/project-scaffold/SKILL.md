# Project Scaffold

只建立目錄、主規範與待填細部規範模板。提問、用途、模板及回覆跟隨目前對話語言，使用者明確指定時優先採用。自行撰寫最終文字，不要求語言選單或另外建立翻譯系統，保留使用者提供的名稱與描述。

## 1. 先提供預覽

沿用已知專案位置及情境；缺少且需要實際建立時，簡短確認目標。使用者要求純模擬時可使用明示的示例專案名，全程不建立檔案。

直接顯示下列預設結構及每項用途，不逐題詢問是否啟用，不要求填寫 JSON。規範與文件為結構分類，不是兩輪必填問卷。

```text
project-root/
├── AGENTS.md                   # 主規範與細則索引
├── .agent-rules/               # 細部規範模板
│   ├── tech-stack.md           # 技術堆疊
│   ├── project-structure.md    # 目錄結構描述
│   ├── tracking.md             # 工作追蹤
│   └── verification.md         # 驗證原則
└── docs/                       # 專案文件主目錄
    ├── requirements/           # 需求文件
    ├── research/               # 研究資料
    ├── architecture/           # 架構文件
    ├── tracking/               # 專案追蹤主目錄（日誌、交接）
    │   ├── devlog/             # 開發過程與驗證紀錄
    │   └── handoff/            # 目前狀態與接續事項
    └── guides/                 # 操作與使用指南
```

這是預設建議而非必須建立的項目。按對話語言撰寫註解，已有明確修改需求時直接套用再預覽，不先要求使用者重答。

結構樹後主動附上操作提示，依對話語言表達：「你可以為這個結構樹新增需要的目錄或文件，刪減不必要的項目，也可以改名、移動位置或調整用途。請直接告訴我要修改的內容，或回覆『沿用預設』。」

## 2. 用自然語言調整

請使用者直接提出新增、移除、改名、移動或用途變更，可一次修改多項。例如：「主規範改為 CLAUDE.md，移除 guides，devlog 改為 journal，新增 meetings 保存會議紀錄。」

- 更新完整結構樹並簡述變更，允許繼續修訂，不回到 Y/n/r、編號逐題問卷或其它1／其它2流程。
- 改名保留用途；父目錄改名或移動時，子項一併跟隨。移除父目錄即移除該骨架中的子項，除非使用者明確要求另存。
- 自訂項目需要用途；同一句已說明時不重問，缺少時才簡短補問 Description。名稱、來源或目標不明、重複或有衝突時才釐清，不猜測。
- 主規範固定在專案根目錄，只建立一份，可用 AGENTS.md、CLAUDE.md 或自訂 Markdown 檔名；自訂名稱不代表 Agent 自動載入。不處理巢狀規範或子專案繼承。
- 規範與目錄分開選擇，不因保留 tracking 模板而強制補建追蹤目錄。使用者移除骨架項目不表示授權刪除既有檔案，既有內容須另行回報處理。
- 全部細則或文件目錄移除時，不建立空殼根目錄或失效索引。只缺未確定內容時保留待填模板，不擴張為技術訪談。

## 3. 確認後生成

參考 [主規範結構](assets/project-template/AGENTS.md)、[細則範例](assets/project-template/.agent-rules/) 與 [通用細則模板](assets/rule-template.md)，以使用者語言整理必要模板，不照抄不相符的英文。

主規範保存共通原則、主從優先序、細則讀取時機與索引；細則只含用途、範圍、待補規則等內容。目錄結構細則可直接包含實際選定樹狀圖。不要建立 PRD、日誌、handoff、README 或其他成果占位文件。

依 [清單格式](references/options.md) 將最新選擇交給 `prepare-plan.mjs`，再以 `scaffold.mjs` 預覽。暫存清單放在目標外，讓一般使用者直接檢視目錄與內容，而非操作內部資料。

呈現最新完整結構、用途、模板摘要及既有衝突後，詢問「確認依此結構建立骨架（Y/n）」。收到 y／Y、使用者明確回覆 Enter 接受預設，或其他明確同意才套用；n／N 不寫入，使用者可繼續修改或取消。未收到回覆、引述或修改要求不視為授權。純模擬的確認也只模擬結果，不執行生成。

確認同一份內容後才使用 `--apply`。若內容或目標狀態改變，重新預覽；新增差異再次確認。不同既有內容不自行覆寫，失敗時保留資料並回報新增、略過、衝突及未完成項目，清理自身暫存清單。

## 工具邊界

Node.js 24+ 可直接執行附帶 `.mjs`，不需安裝套件。從其他工作目錄呼叫時，以 Skill 位置解析腳本路徑。

```text
node scripts/prepare-plan.mjs --target <project> --out <plan.json> --options <choices.json>
node scripts/scaffold.mjs <plan.json>
node scripts/scaffold.mjs <plan.json> --apply
```

目標父目錄須存在，不得在 Skill 安裝目錄內生成。腳本接收最終文字與結構化資料，輸出機器可讀結果，由 Agent 以對話語言解釋，不實作翻譯或問卷。

不安裝 PRD Skill、工具或套件，不執行 Git 或發布，不替使用者編排成果文件。多檔寫入不具交易原子性，避免並行變更目標，失敗不自動回滾。

手動對話及腳本檢查見 [檢視指南](references/manual-validation.md)。
