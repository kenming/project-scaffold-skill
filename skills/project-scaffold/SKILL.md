# 專案骨架

使用本 Skill 內的 [assets/project-template/](assets/project-template/) 作為獨立模板來源，不從開發專案或其他工作目錄取得模板。

## 操作

1. 依使用者指示確認目標專案根目錄；未指定且目前工作目錄明確為目標專案時，使用目前工作目錄。避免在 Skill 安裝目錄內生成專案。
2. 讀取模板的 [目錄規範](assets/project-template/.agent-rules/project-structure.md)，檢查目標路徑、既有規範與檔案衝突。寫入前完成檢查，不沿符號連結或 junction 寫入，也不覆寫或刪除既有檔案。相同內容可略過；不同內容先列出差異，待使用者明確要求合併後再修改。
3. 將模板檔案放入目標根目錄，包含隱藏的 `.agent-rules/`。依目錄規範建立缺少的空目錄；Git 不追蹤空目錄，因此不能只依賴複製模板資料夾。
4. 保留模板 `tech-stack.md` 為零位元組空檔，不將本 Skill 的實作技術套用為目標專案的技術選型。保留使用者既有技術規範。
5. 檢查生成結構、主從規範的相對連結與空檔大小；回報新增、略過、衝突及未完成項目。若中途失敗，說明已寫入內容，不以刪除既有資料回復。

## 範圍

- 文件使用繁體中文；依使用者明確需求調整目錄及用途，並同步修改生成的目錄規範。
- 此版本透過代理的檔案操作建立骨架，不需要安裝套件或執行自訂腳本。
- 生成追蹤規範與「收尾」入口，但建立模板不等於觸發收尾；僅在目標專案使用者發出收尾指令後，才依生成的規範 Commit & Push。
- 不自動初始化 Git、安裝開發工具、建立應用程式或執行 Git Subtree 發布。
