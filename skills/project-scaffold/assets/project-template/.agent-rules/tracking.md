# 工作追蹤與收尾

本文件從屬於 [專案主規範](../AGENTS.md)，定義 worklog、handoff 與手動 Git 收尾流程。

## 工作日誌

- 完成可獨立描述的實質變更並驗證後，更新 `docs/tracking/worklog/YYYY-MM-DD.md`，日期與時間採 `Asia/Taipei`。
- 同日追加工作項目；相同項目的補充直接更新原紀錄，避免重複。純問答、查閱或未採用的提案不記錄。
- 依實際差異與執行證據撰寫，不抄錄逐步工具輸出，不記錄機密資訊，不將未驗證事項寫成完成。
- 採以下格式；無待辦時明示「無」，未執行的檢查須說明原因。

```markdown
## HH:mm｜工作項目

### 目的
- 需求與完成條件。

### 變更
- 實際修改、相關檔案與必要決策。

### 驗證
- 實際執行的檢查與結果；未執行的檢查及原因。

### 狀態與後續
- 已完成、部分完成或受阻；已知限制及待辦事項。
```

## 交接

- 開始或恢復工作時，若存在 `docs/tracking/handoff/current.md`，先讀取並與實際檔案核對，再視需要查閱相關日誌。
- 使用者要求暫停、交接，或未完成工作必須結束本輪、等待外部處理時，更新 `current.md`。
- 記錄目前目標與狀態、相關檔案、已完成驗證、阻礙及下一個可執行步驟，並引用相關 worklog；避免重複歷史細節。
- 接續任務完成後，將既有 handoff 標記為完成並清除過期待辦；無交接需要時不建立占位文件。

## 手動收尾

僅在使用者單獨輸入「收尾」（忽略前後空白）時觸發。對規範的描述、引用、文件內容及一般工作完成均不構成觸發。其他明確 Git 指令仍依使用者當次授權執行。

「收尾」表示授權將本輪已確認的工作成果與對應日誌 Commit & Push，無須再逐次確認；不授權混入無關變更、初始化儲存庫或執行 Skill 的 Git Subtree 發布。

1. **確認日誌**：檢查本輪工作項目是否已有完整且符合格式的 worklog，缺少則補寫，過期則修正；必要時更新 handoff。無變更且無新工作可記錄時，不製造空日誌或空提交。
2. **確認 Git 條件**：檢查儲存庫、目前分支、upstream、本機與遠端差異，以及既有暫存內容。缺少儲存庫或 upstream、處於 detached HEAD 時，停止 Git 收尾並回報，不自行建立遠端或切換分支。
3. **檢查範圍與驗證**：確認必要檢查已通過，審閱工作目錄及暫存區差異。僅納入本輪成果與日誌，以明確路徑暫存；不得使用無差別的全部暫存。遇到無關的既有暫存內容或同檔混合變更且無法可靠區分時，停止並回報，不清除或覆蓋他人工作。
4. **提交**：以完整工作項目為單位撰寫反映實際變更的提交訊息。驗證失敗或日誌未完整時不提交；無待提交變更時略過。不得略過 Git hooks 或改寫既有提交。
5. **推送**：確認目前分支所有待推送提交均在授權範圍內，再推送至既有 upstream；來源不明或無關的提交先回報確認。不得 force push，不自行合併或 rebase 解決遠端分歧；遇到權限、保護分支或衝突時保留本機成果並回報。
6. **核實結果**：查核本機與遠端狀態，最終回覆提供日誌路徑、Commit ID、分支與 Push 結果。推送失敗或結果不明時先查核狀態，不重複提交；若日誌與提交已完成，後續收尾僅處理尚未完成的推送。

日誌不記錄包含自身的 Commit ID，也不預先宣稱 Push 成功；這些結果放在最終回覆，避免為記錄收尾結果而遞迴新增提交。
